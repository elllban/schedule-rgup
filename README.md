# Расписание ЗСФ РГУП

Неофициальный статический сайт с расписанием занятий Западно-Сибирского
филиала РГУП. Проект не связан с вузом и не использует его фирменный стиль.

Первоисточник расписания: https://wsb.rgup.ru/?mod=pages&id=3698

## Как устроено

- Расписание готовится вручную в виде нормализованного CSV (см. ниже).
- Парсер (Python) читает CSV и собирает `web/src/data/schedule.json`.
- Фронтенд (Astro) читает этот JSON и показывает расписание.

## Требования

- Python 3.12+
- Node.js 20+ (для фронтенда, этап 3)

## Установка

```bash
python -m venv parser/.venv
# Windows:
parser\.venv\Scripts\python -m pip install -e "parser/[dev]"
# macOS/Linux:
parser/.venv/bin/python -m pip install -e "parser/[dev]"
```

## CSV-формат

Одна строка — одно правило расписания. Колонки (ровно в этом порядке):

```
Группа,День недели,Начало,Конец,Чётность,Действует с,Действует по,Отдельные даты,Тип занятия,Дисциплина,Преподаватель,Аудитория,Онлайн-ссылка
```

Значения на русском:

- **День недели**: Понедельник … Суббота.
- **Чётность**: `каждую неделю`, `чётная`, `нечётная`. Чётность отсчитывается от
  якорной даты `parity_anchor` в `data/meta.json` (понедельник первой чётной
  недели).
- **Даты**: `ДД.ММ.ГГГГ`. В «Отдельные даты» — через `; `.
- **Тип занятия**: `лекция`, `семинар`, `другое`.
- Поля можно оставлять пустыми (например, «Действует с/по» — тогда берётся весь
  период из `data/meta.json`).

Если «Отдельные даты» заполнены — занятие идёт только в эти даты (чётность
игнорируется). Иначе — по дням недели в диапазоне с учётом чётности.

## Команды

Из корня репозитория (замените `python` на путь к виртуальному окружению, если
нужно):

| Задача | Команда |
| --- | --- |
| Распарсить CSV | `python -m schedule_parser parse` |
| Тесты парсера | `python -m pytest parser/tests` |
| Линтер | `python -m ruff check parser/src parser/tests` |
| Запустить сайт (dev) | `npm --prefix web run dev` |
| Собрать сайт | `npm --prefix web run build` |

Либо через `make` (там же `make parse`, `make test`, `make lint`, `make dev`,
`make build`).

### Парсер

```bash
python -m schedule_parser parse \
  --input data/raw \
  --meta data/meta.json \
  --output web/src/data/schedule.json
```

- Читает все `*.csv` из `--input`, пишет `--output`.
- При ошибках (неверный заголовок, неизвестный день недели и т.п.)
  `schedule.json` **не** перезаписывается; чтобы записать частичный результат,
  добавьте `--force`.
- Предупреждения (пустая дисциплина, расхождение чётности с явной датой и т.п.)
  попадают в отчёт и в `schedule.json`.

### Структура данных

Схема выходного JSON описана в `parser/src/schedule_parser/models.py`.
Ключевые сущности: `meta` (год, семестр, период, источник), `groups`
(группа → события-правила), `occurrences` (развёрнутые конкретные даты —
фронтенд считает только по ним).

### Фронтенд

Astro + TypeScript + Tailwind. Статическая сборка в `web/dist`, без бэкенда.

```bash
cd web
npm install
npm run dev      # локальная разработка
npm run build    # сборка в web/dist
```

Сайт берёт данные из `web/src/data/schedule.json` (генерируется парсером) и
показывает: выбор группы, вид «день»/«неделя» (переход к дню — кликом по заголовку
дня недели), дисклеймер и ссылку на первоисточник. Подстроен под мобильные экраны.

## Деплой (GitHub Pages)

Сайт публикуется на GitHub Pages автоматически: push в ветку `main` →
GitHub Actions собирает `web/` → деплой на `https://<user>.github.io/<repo>/`.

Настройка уже сделана в `.github/workflows/deploy.yml`. Чтобы включить публикацию
в репозитории: **Settings → Pages → Source = GitHub Actions**.

Как обновить расписание в проде:

1. Положить новый CSV в `data/raw/`.
2. `python -m schedule_parser parse` (обновит `web/src/data/schedule.json`).
3. Закоммитить и запушить в `main` — сайт пересоберётся сам.

Базовый путь сайта задан в `web/astro.config.mjs` (`base`). Если репозиторий
переименован или хостинг меняется — поправьте `base` и `site`.

## Дисклеймер

Проект неофициальный. Расписание может содержать неточности — сверяйтесь с
первоисточником.
